🗂️ Project Shadowpay — Master Knowledge Base
Compiled from: the accepted project proposal.  Note: Project Shadowpay is a working project name for a rebrand in progress. Company identity details are held internally until the new brand is announced, so this public page stays codename-only.
Project Overview
  • Working name: Project Shadowpay (final brand name pending legal clearance)
  • What they do: A payments technology platform, partnered with Forefathers Group since 2019
  • Engagement: Brand library refresh plus full website redesign, rebuild, and migration
  • Current stack: WordPress (aging, being retired)
  • New stack: Next.js front end, Sanity CMS, Vercel hosting
Scope of Work
  • Figma Brand Library: Color systems and tokens, typography scales, spacing and layout rules, buttons, forms, navigation, iconography, and responsive rules. The single source of truth for design and development.
  • Website Design: High-fidelity Figma designs for all core marketing and blog pages, with desktop, tablet, and mobile breakpoints and interactive prototypes.
  • Front-End Development: Next.js build with reusable components, performance optimization, custom forms, accessibility compliance, and SEO best practices.
  • Sanity CMS: Structured content models (Platform, Services, Partners, Resources), role-based permissions, real-time collaboration, visual editing, and content scheduling.
  • Migration: WordPress to Sanity with strategic content mapping, scripted transfer, Portable Text restructuring, redirect management, and data validation.
  • SEO & Analytics: Full-site SEO optimization plus Google Analytics and Search Console setup.
Key Constraints
  • Website design and development cannot begin until all brand materials are created, approved, and delivered. Delays in the branding phase push the website timeline directly.
  • The final brand name, domain, and all public-facing SEO copy depend on the naming decision clearing legal review.
  • Total timeline is 28 weeks across the phases, with the Figma Master Library able to run in tandem with migration.

How This Tracker Works:

1. Phases: Work is delivered in 3 milestone phases. The phase pill shows where the project is today; the overall donut is the weighted total across all phases.

2. Editing: Open the live URL with #edit on the end to tick milestone checkboxes, then click Copy progress and paste it to Claude to publish. The plain URL stays read-only for the client.

3. Status updates: To mark a page category done (Design, Dev, SEO, Content, Sanity, Created), tell Claude the page and category. Claude flips the pill ○ → ◐ → ✓ and the progress recalculates automatically.

4. Content strategy: Each page in the content section uses the box hierarchy — plain-text Purpose on top, then the green SEO/AEO box, then the blue Content Created box. The two boxes are siblings, never nested.

5. Progress: Never remove progress already marked complete. Progress only moves forward unless you say to reset.
